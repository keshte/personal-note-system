# Personal Notes System

Навчальна практика з дисципліни "ООП / Інженерія ПЗ" — персональний застосунок для
нотаток на Java 21 + JavaFX 21 + SQLite.

## Швидкий старт

```bash
# 1. (необов'язково) налаштувати реальну відправку email
cp email.properties.example email.properties
#   і вписати свій Gmail App Password.
#   Якщо пропустити цей крок — коди підтвердження просто виводяться в консоль застосунку.

# 2. Запуск
mvn clean javafx:run

# 3. Тести (юніт + інтеграційні)
mvn test
```

База даних (`notes_app.db`) створюється автоматично при першому запуску — окремо
встановлювати SQLite не потрібно. Технології: Java 21, JavaFX 21, SQLite (sqlite-jdbc),
BCrypt (jBCrypt), Jakarta Mail, JUnit 5 + Mockito.

## Функціональність

| Сторінка | Що можна робити |
|---|---|
| **Вхід** | Автентифікація за логіном/паролем, реактивна валідація полів |
| **Реєстрація** | 2 кроки: надсилання коду підтвердження на email → введення коду і створення акаунта |
| **Нотатки** (головний екран) | Створення/редагування/видалення нотаток, пошук за текстом (заголовок + вміст), фільтр за категорією, прив'язка кількох категорій до нотатки |
| **Категорії** | CRUD довідника категорій (назва + колір) |
| **Профіль** | Аватар (автогенерований), зміна імені, опису, пароля, email (з підтвердженням кодом), експорт нотаток у TXT/CSV |
| **Налаштування** | Перемикач світлої/темної теми (зберігається між запусками) |
| **Звіти та статистика** | Кругова діаграма кількості нотаток по категоріях, експорт TXT/CSV |
| **Адмін-панель** | Демонстраційний перелік користувачів (логін, email, дата реєстрації, кількість нотаток) |
| **Про програму** | Назва, іконка, короткий опис і версія застосунку |

Іконка застосунку (згенерована програмно — нотатник з олівцем) встановлюється для вікна
один раз при старті й лишається на всіх екранах, оскільки вони перевикористовують той самий
`Stage`; додатково показана як лого на екранах входу/реєстрації/про програму.

## Архітектура

Тришарова архітектура (Presentation → Business Logic → Data Access):

```
controller/  →  service/ (+ facade/)  →  repository/  →  db/ (SQLite)
     ↑                                        ↑
  viewmodel/                              mapper/ (Data Mapper)
     ↑                                        ↑
   FXML                                    model/ (entities)
```

- **model/** — сутності (`User`, `Note`, `Category`, `Profile`, `VerificationCode`),
  усі успадковують `BaseEntity` з абстрактним `validate()` (поліморфізм).
- **dto/** — об'єкти для передачі даних між шарами, не розкривають внутрішню структуру сутностей.
- **mapper/** — Data Mapper: перетворення `ResultSet` ↔ сутність, відокремлено від SQL-логіки.
- **repository/** — інтерфейси + реалізації на SQLite (Repository pattern), плюс
  `LoggingNoteRepositoryProxy` (Proxy pattern) для наскрізного логування.
- **db/** — `DatabaseManager` (Singleton) + `ConnectionPool`.
- **service/** — бізнес-логіка і валідація (`AuthService`, `NoteService`, `CategoryService`,
  `ProfileService`, `AdminService`).
- **facade/** — `ReportFacade` ховає деталі статистики/експорту за простим API.
- **core/** — `AppContext` (Singleton, легкий DI/IoC-контейнер), `SceneNavigator` (навігація
  між сторінками + застосування теми), `ThemeManager` (світла/темна тема, персистить вибір).
- **viewmodel/** — `NoteViewModel` з JavaFX-властивостями для двостороннього біндінгу форми.
- **controller/** — presentation-шар, усі повільні операції (звернення до БД, відправка email)
  виконуються в `javafx.concurrent.Task`, щоб не блокувати UI-потік.

## Використані патерни проєктування

Singleton (`DatabaseManager`, `AppContext`) · Repository · Data Mapper ·
Lazy Initialization (категорії нотатки підвантажуються при першому зверненні) ·
DTO · Builder (`NoteDTO.Builder`) · Facade (`ReportFacade`) ·
Proxy (`LoggingNoteRepositoryProxy`) · DI/IoC (`AppContext`) ·
MVVM-біндінг (`NoteViewModel`, двосторонній bind полів форми)

## База даних

6 таблиць, 3НФ: `users` —1:1→ `profiles`, `users` —1:N→ `notes`, `notes` ←N:M→ `categories`
через `note_categories`, окремо `verification_codes` для кодів підтвердження реєстрації/зміни email.
Індекси, тригер автооновлення `updated_at`, VIEW `view_notes_with_categories`.
Див. `src/main/resources/schema.sql` та ER-діаграму в `docs/er-diagram.mmd`.

Збереження нотатки разом з категоріями виконується в одній транзакції
(`BEGIN`/`COMMIT`/`ROLLBACK`) — див. `SqliteNoteRepository.saveWithCategories`.

## Безпека

- Паролі хешуються через BCrypt, ніде не зберігаються і не логуються у відкритому вигляді.
- Креденшели email НЕ зберігаються в коді — читаються зі змінних середовища
  (`EMAIL_USERNAME`, `EMAIL_APP_PASSWORD`) або з `email.properties`, який доданий у `.gitignore`.
  Див. `email.properties.example`.
- SQL-запити виключно через `PreparedStatement` (захист від SQL-ін'єкцій).
- **Адмін-панель — навчальний прототип "для демонстрації"**: доступна будь-якому авторизованому
  користувачу з головного меню, без перевірки ролі. Для реального використання потрібно додати
  систему ролей (наприклад, поле `role` у таблиці `users` і перевірку в `SessionManager`/`AuthService`
  перед показом пункту меню та відкриттям сторінки).

## Тестування

- `src/test/.../service/AuthServiceTest.java`, `NoteServiceTest.java` — юніт-тести бізнес-логіки
  на моках (Mockito), без звернення до реальної БД.
- `src/test/.../repository/NoteRepositoryIntegrationTest.java` — інтеграційний тест, що
  перевіряє транзакційне збереження N:M-зв'язку та lazy loading поверх справжньої SQLite.
- `docs/MANUAL_TESTING.md` — 20 сценаріїв ручного тестування (форма test-case).

### Якщо `mvn test` падає з "Could not self-attach to current VM" (Mockito)

Це не помилка коду проєкту, а конфлікт версії Mockito з дуже новою JDK (спостерігалось на JDK 25).
У `pom.xml` вже додано фікс — Mockito явно підключений як Java-агент через `-javaagent` в
`maven-surefire-plugin`, це офіційно рекомендований спосіб обходу для JDK 21+.

Якщо помилка лишається:
1. Переконайтесь, що `mvn test` реально підтягнув версію з `pom.xml` (Mockito 5.18.0), а не стару
   версію з кешу: `mvn -U clean test`.
2. Якщо в логах є `Error opening zip file or JAR manifest missing` для якогось jar (наприклад
   `byte-buddy-agent`) — це пошкоджений файл у локальному `.m2` кеші, а не помилка проєкту.
   Видаліть відповідну папку з `~/.m2/repository/net/bytebuddy/` (Windows: `C:\Users\<ім'я>\.m2\repository\net\bytebuddy\`)
   і повторіть `mvn -U test`, щоб Maven перезавантажив файл.

## Відомі обмеження

- Реальний PDF-експорт не реалізований (лише TXT/CSV) — генерація PDF потребує додаткової
  бібліотеки (наприклад, Apache PDFBox). За потреби додайте залежність
  `org.apache.pdfbox:pdfbox` і новий метод в `ReportFacade` за аналогією з `exportToTxt`.
- Адмін-панель — демонстраційна, без розмежування прав доступу (див. розділ "Безпека").
- Темна тема покриває основні власні стилі та найпоширеніші контроли (кнопки, поля вводу,
  списки, таблиці, меню); окремі рідковживані стандартні контроли JavaFX можуть лишитись
  у стандартних кольорах.
- На Windows консоль за замовчуванням не завжди в UTF-8, тому кириличні повідомлення в логах
  (наприклад, код підтвердження, який виводиться, якщо email не налаштовано) можуть відображатись
  "кракозябрами". Це не помилка застосунку — досить виконати `chcp 65001` у терміналі перед запуском.
